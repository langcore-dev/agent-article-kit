# 採用広報インタビュースキル

社員へのインタビューで集めた一次情報から、採用広報・社員紹介の記事ドラフトを生成するスキル。進め方は2つある。

| 進め方 | 使う場面 |
|---|---|
| その場でインタビュー | 対象者が端末の前にいて、質問に直接答える |
| 文字起こしから作る | 会議ツールの録音などで取材済み。文字起こしを読み込み、足りない点だけ追加で聞く |

呼び出し例:

```text
/interview
/interview transcripts/2026-10-20-yamada.txt
```

## 前提ファイル

すべてプロジェクトルートからの相対パスで参照する。

- `.claude/shared/workflow-common.md` - プロフィール、引数、作業ファイル、仕上げの共通手順
- `.claude/shared/writing-rules.md` - 文章ルール、タイトル指針、行動経済学テクニック
- `.claude/skills/interview/interview-guide.md` - 質問カテゴリ、職種別の質問、深掘りルール
- `.claude/skills/interview/article-template.md` - 記事の構成テンプレート
- `.claude/agents/article-writer.md` - 記事生成サブエージェント

## ワークフロー

### Phase 0: 準備

`.claude/shared/workflow-common.md` の「1. 準備」を行う（プロフィールの読み込み、引数の確認、途中の作業の確認）。インタビュアーはプロフィールの書き手とする。

引数で文字起こしのファイルが渡されていれば、進め方は「文字起こしから作る」に決まる。

### Phase 1: コンテキスト初期化

#### 1-1. 記事の設定

AskUserQuestion を1回だけ呼び、次の質問をまとめて聞く。引数やプロフィールから明らかな項目は質問から外す。

```
questions:
  - header: "目的"
    question: "この記事の目的は何ですか？"
    options:
      - label: "採用広報（エンジニア）"
        description: "エンジニア候補者に向けた社員インタビュー"
      - label: "採用広報（エンジニア以外）"
        description: "PM、デザイナー、セールス、コーポレートなどの候補者に向けた社員インタビュー"
      - label: "技術・専門性のブランディング"
        description: "チームの技術力や専門性を伝えるインタビュー"
      - label: "チーム・社員紹介"
        description: "チームの雰囲気や文化、人柄を伝えるインタビュー（社内向けにも使える）"
  - header: "読者"
    question: "主な読者は誰ですか？"
    options:
      - label: "中途の候補者"
        description: "経験者採用の候補者"
      - label: "新卒の候補者"
        description: "新卒採用の候補者"
      - label: "社内メンバー"
        description: "社内報として読む同僚"
  - header: "進め方"
    question: "インタビューの進め方を選んでください"
    options:
      - label: "その場でインタビュー"
        description: "対象者がこの画面で質問に答える"
      - label: "文字起こしから作る"
        description: "取材の文字起こしファイルを読み込み、足りない点だけ追加で聞く"
  - header: "インタビュアー"
    question: "インタビュアー（記事の書き手）は誰ですか？"
    options:
      - label: "{プロフィールの名前}"
        description: "{プロフィールの所属}・{プロフィールの役職}"
      - label: "別の人"
        description: "Other で名前・所属・役職を入力"
```

#### 1-2. 対象者の情報

文字起こしから作る場合は、先に文字起こしのファイルパスを聞いて Read で読み込む（引数で渡されていれば不要）。

対象者の情報（名前、職種・役職、チーム、入社時期）を通常のメッセージで聞く。文字起こしから読み取れた項目は、確認だけにする。

> インタビュー対象者の情報を教えてください（名前、職種・役職、チーム、入社時期）。
> 例: 山田太郎、バックエンドエンジニア、プラットフォームチーム、2023年4月入社

回答を受けたら、`.claude/shared/workflow-common.md` の「2. 作業ファイル」の形式で `articles/.work/{slug}/material.md` を作る（slug は `{YYYY-MM-DD}-{名前のローマ字}`、`status: collecting`）。コンテキストには目的、読者、進め方、インタビュアー、対象者プロフィールを書く。文字起こしから作る場合は、文字起こしのファイルパスも書く。

### Phase 2A: その場でインタビュー

`.claude/skills/interview/interview-guide.md` を読み込み、質問カテゴリ、対象者の職種に合う質問、深掘りルールを把握する。

1. Phase 1 のコンテキストに基づき、最初の質問を決める
2. AskUserQuestion で1問ずつ質問する
   - 回答の参考になる選択肢を2〜3個用意しつつ、「Other」からの自由入力を基本とする
3. 回答を深掘りルールに照らして判定し、必要なら追加質問をする（同じ質問で最大2回）
4. 次の質問は前の回答のキーワードを拾って生成する
5. 全5カテゴリからバランスよく、合計5〜8問を目安にする。最後は「未来・ビジョン」から選ぶ
6. 回答を受け取るたびに作業ファイルの「素材」に追記する

```
- カテゴリ: {カテゴリ名}
  質問: {質問文}
  回答: {回答文}
  深掘り:
    - 質問: {深掘り質問}
      回答: {深掘り回答}
```

#### 質問生成のルール

- シード質問をそのまま使わず、対象者の職種、プロフィール、前の回答に合わせて変える
- 自然な会話口調にする（「〜について教えてください」「〜はいかがですか」）
- 対象者が答えやすいよう、具体的な切り口を示す

### Phase 2B: 文字起こしから作る

1. 文字起こしを読み、発言を質問と回答の組に整理して作業ファイルの「素材」に書く
   - 発言者が分かる場合は、インタビュアーと対象者の発言を区別する
   - フィラー（「えー」「あのー」）や言い直しは除くが、言い回しの特徴は残す
   - 各回答に、interview-guide.md の5カテゴリのどれに当たるかを付ける
2. interview-guide.md の深掘りルールで不足を洗い出す
   - 5カテゴリのうち触れていないもの
   - 具体例・数値・固有名詞がない回答
   - 記事の締めに使える「未来・ビジョン」の発言がない
3. 不足があれば、AskUserQuestion で追加の質問をする（最大3問）。ユーザーが対象者本人でない場合は、「分からない」を選べる選択肢を入れる
4. 追加の回答も作業ファイルの「素材」に追記する

### Phase 3: ドラフト生成

作業ファイルを `status: drafting` にし、Agent ツールで `article-writer` サブエージェントを起動する。素材は作業ファイルに入っているので、プロンプトにはパスと設定だけを渡す。

```
以下の作業ファイルのインタビュー記録から記事を作成してください。

## 作業ファイル
articles/.work/{slug}/material.md

## 出力先
articles/{slug}.md

## 記事の目的
{目的}

## 読者
{読者}

## インタビュアー
- 名前: {名前}
- 所属: {所属}

## 対象者
- 名前: {名前}
- 職種・役職: {職種・役職}
- チーム: {チーム}
- 入社時期: {入社時期}
```

### Phase 4: 仕上げ

作業ファイルを `status: finishing` にし、`.claude/shared/workflow-common.md` の「3. ドラフト後の仕上げ」を行う（yomiyasu で推敲 → textlint → 提示と確認）。
