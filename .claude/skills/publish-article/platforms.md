# 公開先ごとの形式

どの公開先でも、記事の文章そのものは変えない。各形式の仕様は変わることがあるので、書き出す前に迷う点があれば公式のヘルプを確かめる。

## note（`note.md`）

note のエディタは Markdown の一部しか解釈せず、タイトルは本文と別の欄に入れる。

- 1行目に `タイトル: {タイトル}` を書き、空行を1つ置いてから本文を続ける。本文に `# タイトル` の行は入れない
- 見出しは `##`（大見出し）と `###`（小見出し）だけを使う。`####` 以下は `###` にする
- 表は使えないので、箇条書きに変換する（例: プロフィール表 → 「- 名前: 山田太郎」の形）
- 引用ブロック（`>`）、箇条書き、番号つきリスト、コードブロック、リンクはそのまま使える
- 末尾に、次の行を `<!-- -->` のコメントで残す: 「見出し画像を設定する」「ハッシュタグを3〜5個つける（例: #採用 #エンジニア採用 #{会社名}）」

## Zenn（`zenn.md`）

Zenn CLI の記事の形式で書き出す。本文に `# タイトル` の行は入れない（タイトルは front matter に書く）。

```markdown
---
title: "{タイトル}"
emoji: "{記事の内容に合う絵文字1つ}"
type: "{tech または idea}"
topics: ["{タグ}", "{タグ}"]
published: false
---

{本文}
```

- `type`: 技術の解説や実装の話は `tech`、採用・組織・キャリアの話は `idea`
- `topics`: 英小文字と数字で最大5個（例: `["ci", "githubactions", "career"]`）
- `published` は `false` のままにする（公開は人が判断する）
- 表、引用、コードブロックはそのまま使える

## Qiita（`qiita.md`）

Qiita CLI の記事の形式で書き出す。本文に `# タイトル` の行は入れない。

```markdown
---
title: {タイトル}
tags:
  - {タグ}
  - {タグ}
private: false
updated_at: ''
id: null
organization_url_name: null
slide: false
ignorePublish: false
---

{本文}
```

- `tags`: 1〜5個。技術名は Qiita で一般的な表記にする（例: `GitHubActions`, `TypeScript`）
- Qiita は技術情報の共有の場なので、採用広報の色が強い記事（技術の話がほとんどない記事）を選んだ場合は、その旨をユーザーに伝える
- 表、引用、コードブロック、注記（`:::note info`）が使える

## はてなブログ（`hatena.md`）

はてなブログの Markdown モードの本文として書き出す。

- 1行目に `タイトル: {タイトル}` を書き、空行を1つ置いてから本文を続ける。本文に `# タイトル` の行は入れない
- はてなブログの Markdown モードでは `#` が大見出し、`##` が中見出し、`###` が小見出しになる。記事の `##` は `#` に、`###` は `##` に1段上げる
- 表、引用、コードブロックはそのまま使える
- 冒頭のポイントの後に `[:contents]` を入れると目次になる（セクションが4つ以上のときだけ入れる）

## 社内Wiki など（`wiki.md`）

Notion、Confluence、esa などに貼る想定の、一般的な Markdown として書き出す。

- `# タイトル` の行を残す
- 冒頭に、書き手、公開日、元の記事ファイルのパスを1行で添える
- 外部公開用の挨拶文や「一緒に働きませんか」のような採用の呼びかけは、社内向けなら残すかをユーザーに確認する

## 告知文とアイキャッチ（`promotion.md`）

選ばれたものだけを、次の見出しで書く。

### X の告知文

- 3案。それぞれ URL を除いて140字以内（全角1字を1字と数える）
- 案ごとに切り口を変える（数値・成果を前に出す / 人物の一言を引用する / 読者への問いかけ）
- 末尾に `{記事のURL}` と、ハッシュタグを2個まで

### LinkedIn・Facebook の告知文

- 300字程度で1案。誰に向けた記事か、何が分かるかを最初の2行に入れる
- 末尾に `{記事のURL}`

### Slack の社内告知

- 3〜4行。誰の記事か、何の話か、読んでほしい人を書き、`{記事のURL}` で終える

### アイキャッチ画像の案

- 画像に入れる文字の案を3つ（各20字以内。タイトルを短くしたもの、数値を前に出したもの、人物の一言）
- 画像生成 AI 向けの指示文を1つ（英語。人物の顔や実在の会社のロゴは生成させない。文字は入れない指定にし、文字は後から重ねる）
- 推奨サイズ: note は 1280×670px、X の共有カードは 1200×630px
